# Tiki Debug Skinning Bridge

This report documents the first experimental bridge from the solved static runtime mesh viewer into a visible skinned Tiki preview.

It does **not** claim full correct body-type playback yet.

## Current Result

- The real Tiki mesh `dragon_tiki_2024.bdae` still resolves and renders through the validated static runtime mesh path.
- The captured skin palette and weight artifacts from the handoff bundle are now parseable enough to drive a first skinned preview.
- The old "huge head" result is now better explained as a skinning-space problem, not a broken mesh decode.
- Applying the captured palette inside helper-root `0x27190975200` local space and round-tripping back out yields the first visibly plausible captured skinned Tiki pose.
- A second Tiki-specific branch-mix correction now materially improves on the single-root variant: slots `4/9` use helper `0x27190978200`, slot `5` uses `0x27190979400`, and slot `10` uses `0x2719097aa00`, which sharply reduces the remaining oversized head / upper-mask distortion.
- A tail-only animated preview was emitted using the validated `0xBEF48` stride-4 local quaternion override for slots `21`, `22`, `23`.
- A workspace GUI now defaults to the visually validated static mesh path and leaves skinned deformation behind an explicit experimental checkbox.
- Fresh read-only IDA checks reinforce that the current deformation error is in palette/helper-space composition: `0x7FF720A60020` uploads composed `bone_matrices` / `weight_mask` parameters, while `0x7FF720A5CED0` contains a concrete influence loop using `u8` palette slots multiplied by `64` bytes and float weights.
- The skinned preview now uses a new `rest_pose_unapply` mode: each file vertex is treated as already rest-posed, moved back through its per-vertex blended rest palette, then moved forward through the frame palette. This prevents the old rest-pose double-deformation/crushed body.
