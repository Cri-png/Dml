## Current Interpretation

The old “moves briefly then tweaks” behavior is now best explained by two separate issues:

1. `CONFIRMED`: raw key times were initially treated as frame numbers, but IDA proves mode-3 time rows are scaled by `33.333332`.
2. `STRONGLY SUPPORTED`: many channels naturally end far earlier than raw key `250`, so a single global GIF timeline clamps much of the rig unless the real clip/subclip window is known.
3. `CONFIRMED`: `dragon_gorillabody_anim.bdae` contains an executable-consumed named clip table, so the viewer should expose selectable animation states such as `idle_basic`, `idle_walk`, `levelup`, `attack`, and `win` instead of treating the whole shared BDAE as one animation.
4. `CONFIRMED`: `0x7FF7209FBC20` selects and clamps a clip window before downstream evaluation. The current viewer's `clip-local-ms` export is therefore a useful diagnostic preview, not a final game-equivalent timing model.

The normalized-track export is intentionally not a production playback mode. It is useful because it keeps every channel visibly moving across the diagnostic loop while we continue searching for the real clip timing and final evaluator sinks.
